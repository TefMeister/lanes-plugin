# Lanes extras

Every extra below is optional: each PC switches it on or off (`features.py on|off <name>`). A new
install chooses at `/lanes:setup`; a PC that had Lanes before keeps what it had. Sets marked **best
together** are suggested as a pair. Written by `tools/features.py doc`; edit the list there, not here.

## Everyday helpers

Small things for every session. Each one works on its own.

- **The green look** (`theme`): gives this terminal window the plugin's old green-monitor look; it can be taken off again any time. [Read more](https://github.com/TefMeister/lanes-plugin/blob/main/plugins/lanes/commands/theme.md)
- **Lanes version first** (`version_line`): every session opens with one line naming the Lanes version it runs, so an old copy is seen at a glance. [Read more](https://github.com/TefMeister/lanes-plugin/blob/main/plugins/lanes/hooks/version-line)
- **Check before agreeing** (`talk_rule`): Claude never says "you are right" before checking what you said. [Read more](https://github.com/TefMeister/lanes-plugin/blob/main/plugins/lanes/hooks/talk-rule)
- **Straight talk** (`straight_talk`): Claude talks like a friend: warm but honest and direct, and when you miss something obvious it says so with a light ribbing instead of "easy to miss". [Read more](https://github.com/TefMeister/lanes-plugin/blob/main/plugins/lanes/hooks/straight-talk)
- **Reply check** (`reply_check`): when Claude forgets one of the lines it promised to put in a reply (for example the green tick that says you may close the game), it is made to add it straight away. [Read more](https://github.com/TefMeister/lanes-plugin/blob/main/plugins/lanes/hooks/reply-check.py)
- **Saving in turn** (`git_queue`): when several Claude windows work at once, they save to GitHub one after another, so one never saves into another's half-done work. [Read more](https://github.com/TefMeister/lanes-plugin/blob/main/plugins/lanes/hooks/git-queue.py)
- **One window per game** (`project_guard`): only one Claude window at a time changes a game's files; a second one is stopped with one line until the first is done, and saying "take over <game>" hands it over. [Read more](https://github.com/TefMeister/lanes-plugin/blob/main/plugins/lanes/hooks/project-guard.py)
- **Rest reminder** (`rest_reminder`): once a session, past the rest time you set (midnight unless you change it), Claude says so in one line at the top of its reply. [Read more](https://github.com/TefMeister/lanes-plugin/blob/main/plugins/lanes/hooks/rest-reminder.py)
- **Use the tools, grow the tools** (`tools_rule`): Claude uses the helper programs this PC has (menu routes, the pretend headset, the VR fault reports, the live game connectors) before doing a job by hand, writes down what it learns, and turns a job done by hand twice into a small tool. [Read more](https://github.com/TefMeister/lanes-plugin/blob/main/plugins/lanes/docs/PROTOCOL.md#33-use-every-tool-you-have-record-what-helps-grow-the-toolset-0850-2026-10-24)
- **Privacy guard** (`privacy_guard`): nothing you save to GitHub can carry your Windows login name, your home folder's location or your e-mail address; anything that would is stopped before it leaves the PC. [Read more](https://github.com/TefMeister/lanes-plugin/blob/main/plugins/lanes/docs/PROTOCOL.md#34-the-privacy-guard-no-login-no-home-paths-no-e-mail-on-github-0860-2026-10-25)
- **Games check at session start** (`games_check`): each session starts by checking your project games: one a store has updated (a mod may need a fix), one removed or moved, a new project with no game found yet. [Read more](https://github.com/TefMeister/lanes-plugin/blob/main/plugins/lanes/tools/games.py)
- **Remote Control in every session** (`remote_control`): every Claude session on this PC can be watched and typed into from the Claude phone app or claude.ai, or from a session on your other PC; it needs a claude.ai account. [Read more](https://github.com/TefMeister/lanes-plugin/blob/main/plugins/lanes/docs/PROTOCOL.md#35-remote-control-in-every-session-0870-2026-10-26)
- **Blink when Claude is done** (`taskbar_flash`): the terminal's button on the taskbar blinks when Claude finishes or waits for an answer, so a window hidden behind a game is not missed. [Read more](https://github.com/TefMeister/lanes-plugin/blob/main/plugins/lanes/tools/taskbar_flash.py)
- **Keep full conversation logs** (`keep_transcripts`): keeps a copy of every conversation on this PC after Claude Code's own 30-day clean-up (about 1 GB a month of disk). [Read more](https://github.com/TefMeister/lanes-plugin/blob/main/plugins/lanes/docs/PROTOCOL.md#21-keep-conversations-short-an-earlier-summary-that-loses-nothing-0630-2026-10-13)
- **No clashes** (`clash_guard`): things that must not run at the same time (two weekly check-ups, two Lanes installs, two recordings, a second game beside a running one) are kept apart on both your PCs: the second is stopped with one line saying what is running where. [Read more](https://github.com/TefMeister/lanes-plugin/blob/main/plugins/lanes/docs/CLASHES.md)
- **Copies kept level with GitHub** (`keep_level`): after each session, every copy on this PC that is only behind GitHub is brought up to date, and a project your other PC started is copied here; a copy with unsaved work is never touched. [Read more](https://github.com/TefMeister/lanes-plugin/blob/main/plugins/lanes/docs/TWO-PCS.md)
- **Saving to GitHub in the background** (`keeper`): the windows that build never upload: they save their work and hand it over, and a keeper on your second PC uploads it and keeps your GitHub pages up to date. [Read more](https://github.com/TefMeister/lanes-plugin/blob/main/plugins/lanes/docs/ONE-PC.md)
- **Switch off only when everything is saved** (`shutdown_guard`): when you ask Claude to switch the PC off after its work, it waits until no game runs, no other window is busy and everything is on GitHub, then switches off by itself; it never forces. [Read more](https://github.com/TefMeister/lanes-plugin/blob/main/plugins/lanes/tools/switch_off.py)

## Keeping your tools up to date (best together)

The reminder brings the weekly tool check round, and the test builds make sure an update it installs does not break what you build.

- **Weekly tool reminder** (`gu_nudge`): one line at the start of a session when the weekly check for newer versions of your tools is due. [Read more](https://github.com/TefMeister/lanes-plugin/blob/main/plugins/lanes/docs/PROTOCOL.md#23-the-weekly-tool-check-lanesgu-0670-2026-10-14). Goes well with: Lanes updates itself, Fresh-session nudge, Session hand-on, Hold Lanes updates during a test, Test builds before updates, Installs with no Yes click.
- **Lanes updates itself** (`auto_update`): a new Lanes version installs by itself in the background, never while a game or a test is running, and the next session says what it added; a failed update leaves the old version working. [Read more](https://github.com/TefMeister/lanes-plugin/blob/main/plugins/lanes/tools/auto_update.py). Goes well with: Weekly tool reminder, Fresh-session nudge, Session hand-on, Hold Lanes updates during a test, Test builds before updates, Installs with no Yes click.
- **Fresh-session nudge** (`fresh_nudge`): when a job is finished and saved and the conversation has grown long, one line suggests starting a fresh one, because every step of a long one costs more; never in the middle of a job. [Read more](https://github.com/TefMeister/lanes-plugin/blob/main/plugins/lanes/tools/handon.py). Goes well with: Weekly tool reminder, Lanes updates itself, Session hand-on, Hold Lanes updates during a test, Test builds before updates, Installs with no Yes click.
- **Session hand-on** (`hand_on`): on your yes to a next job, Claude writes the job down for a new window, opens it, and closes the old window once everything is saved. [Read more](https://github.com/TefMeister/lanes-plugin/blob/main/plugins/lanes/commands/next.md). Goes well with: Weekly tool reminder, Lanes updates itself, Fresh-session nudge, Hold Lanes updates during a test, Test builds before updates, Installs with no Yes click.
- **Hold Lanes updates during a test** (`update_hold`): while you test something, Lanes can be told not to update itself until the test is over (or 12 hours pass), so nothing changes under the test. [Read more](https://github.com/TefMeister/lanes-plugin/blob/main/plugins/lanes/docs/PROTOCOL.md#43-hold-lanes-updates-while-a-test-runs-lanes-next-2026-11-01). Goes well with: Weekly tool reminder, Lanes updates itself, Fresh-session nudge, Session hand-on, Test builds before updates, Installs with no Yes click.
- **Test builds before updates** (`update_safety`): an update that could break what you build (a compiler, Visual Studio, Python, Blender) is tried on a test build first and undone if your work stops building. [Read more](https://github.com/TefMeister/lanes-plugin/blob/main/plugins/lanes/docs/PROTOCOL.md#31-test-build-before-keeping-an-update-0830-2026-10-23). Goes well with: Weekly tool reminder, Lanes updates itself, Fresh-session nudge, Session hand-on, Hold Lanes updates during a test, Installs with no Yes click.
- **Installs with no Yes click** (`quiet_installs`): one Windows Yes click, once, lets Lanes install and update programs from Windows' own catalogue without asking again, so nothing ever sits waiting for a click while you are away; it can do nothing else. [Read more](https://github.com/TefMeister/lanes-plugin/blob/main/plugins/lanes/docs/PROTOCOL.md#49-installs-with-no-yes-click-01100-2026-11-11). Goes well with: Weekly tool reminder, Lanes updates itself, Fresh-session nudge, Session hand-on, Hold Lanes updates during a test, Test builds before updates.

## The weekly check-up (best together)

Every game run's logs are kept on shelves, and the weekly check-up reads them together with the research, tool and tidiness checks.

- **Keep every run's logs** (`gold_digger`): after every game run its logs and fault reports are kept on labelled shelves (camera, guns, jitter, menus and so on) in your transfer folder, never deleted, and read once a week for anything new. [Read more](https://github.com/TefMeister/lanes-plugin/blob/main/plugins/lanes/commands/gd.md). Goes well with: Weekly check-up reminder, The weekly check-up goes first, Network safety check, Forgotten space finder, Every game run noted, Code health, Out of Date.
- **Weekly check-up reminder** (`fullscan`): one line at the start of a session when the weekly check-up (the logs, research, tool versions, tidiness, then save) is due. [Read more](https://github.com/TefMeister/lanes-plugin/blob/main/plugins/lanes/commands/fullscan.md). Goes well with: Keep every run's logs, The weekly check-up goes first, Network safety check, Forgotten space finder, Every game run noted, Code health, Out of Date.
- **The weekly check-up goes first** (`scan_priority`): while the weekly check-up runs, the other Claude windows on this PC finish their step, save and wait, and carry on when it is done. [Read more](https://github.com/TefMeister/lanes-plugin/blob/main/plugins/lanes/docs/PROTOCOL.md#48-the-full-scan-goes-first-01100-2026-11-11). Goes well with: Keep every run's logs, Weekly check-up reminder, Network safety check, Forgotten space finder, Every game run noted, Code health, Out of Date.
- **Network safety check** (`netcheck`): once a week, without changing anything, checks this PC's firewall, antivirus, remote logins and Windows updates, and says what changed since last week. [Read more](https://github.com/TefMeister/lanes-plugin/blob/main/plugins/lanes/tools/netcheck.py). Goes well with: Keep every run's logs, Weekly check-up reminder, The weekly check-up goes first, Forgotten space finder, Every game run noted, Code health, Out of Date.
- **Forgotten space finder** (`spacecheck`): once a week, lists what takes space on your drives in three groups (safe to clear, probably safe, yours to decide); it never deletes anything. [Read more](https://github.com/TefMeister/lanes-plugin/blob/main/plugins/lanes/tools/spacecheck.py). Goes well with: Keep every run's logs, Weekly check-up reminder, The weekly check-up goes first, Network safety check, Every game run noted, Code health, Out of Date.
- **Every game run noted** (`collector`): every time one of your project games runs, its load, temperature, hangs, logs and crashes are noted quietly and kept with the other run logs. [Read more](https://github.com/TefMeister/lanes-plugin/blob/main/plugins/lanes/docs/PROTOCOL.md#44-the-always-on-collector-lanes-next-2026-11-04). Goes well with: Keep every run's logs, Weekly check-up reminder, The weekly check-up goes first, Network safety check, Forgotten space finder, Code health, Out of Date.
- **Code health** (`code_health`): once a week, your own helper programs are read through again and tidied only where it cannot change how they work, after a working copy is saved. [Read more](https://github.com/TefMeister/lanes-plugin/blob/main/plugins/lanes/commands/ch.md). Goes well with: Keep every run's logs, Weekly check-up reminder, The weekly check-up goes first, Network safety check, Forgotten space finder, Every game run noted, Out of Date.
- **Out of Date** (`out_of_date`): once a week, checks that everything you published on GitHub is as new as the work behind it, and brings it level. [Read more](https://github.com/TefMeister/lanes-plugin/blob/main/plugins/lanes/commands/od.md). Goes well with: Keep every run's logs, Weekly check-up reminder, The weekly check-up goes first, Network safety check, Forgotten space finder, Every game run noted, Code health.

## For VR mods (best together)

One keeps the headset picture down to the gameplay, the other reports when that picture or the hands are not smooth, so its reports are about the mod and not about blur.

- **VR fault reports** (`begone_ride`): a quiet helper turns each headset test of a mod into a short report on stepped movement and hands that do not follow the controllers. [Read more](https://github.com/TefMeister/BeG0nE). Goes well with: VR fault reports save themselves, Gameplay only in VR.
- **VR fault reports save themselves** (`begone_autosave`): each VR fault report is saved to GitHub by itself, so one is never left only on this PC. [Read more](https://github.com/TefMeister/BeG0nE). Goes well with: VR fault reports, Gameplay only in VR.
- **Gameplay only in VR** (`vr_effects_off`): sessions switch off every blur and screen effect a game paints over the picture, such as motion blur, blood on the screen and the low-health tint. [Read more](https://github.com/TefMeister/lanes-plugin/blob/main/plugins/lanes/docs/PROTOCOL.md#19-gameplay-only-every-blur-and-screen-effect-off-in-vr-0600-2026-10-12). Goes well with: VR fault reports, VR fault reports save themselves.

## Filming the VR tests (best together)

One films the game during every VR test so each fault can be seen picture by picture, the other takes those videos off the PC again once nothing needs them.

- **Film every VR test** (`begone_record`): OBS films the game's own window (never the whole screen) during every VR test, so each fault in the report can be looked at picture by picture. [Read more](https://github.com/TefMeister/lanes-plugin/blob/main/plugins/lanes/docs/PROTOCOL.md#26-the-recording-and-the-jitter-log-side-by-side-0760-2026-10-17). Goes well with: Test videos clean up after themselves.
- **Test videos clean up after themselves** (`begone_video_tidy`): the videos of VR tests are taken off the PC once nothing needs them (the game was tested again on a later day, or two weeks passed); the cut pictures and the reports stay. [Read more](https://github.com/TefMeister/lanes-plugin/blob/main/plugins/lanes/docs/PROTOCOL.md#38-beg0ne-videos-clean-up-after-themselves-0900-2026-10-27). Goes well with: Film every VR test.

## Our own apps and libraries

The other things we built for flat-to-VR work, each from its page on TefMeister's GitHub. Each one is useful on its own.

- **Window View** (`ours_window_view`): hangs any desktop window (Hand Freeze, Hand Poser, a browser) inside any OpenXR game (Direct3D 11 and 12), see-through as you like, used with the mouse and keyboard (Page Up / Page Down) or the VR controllers while the game only hears the controllers, so a mod can be tuned without taking the headset off. [Read more](https://github.com/TefMeister/window-view-vr)
- **Hand Poser** (`ours_hand_poser`): a compact window of sliders that poses the player's fingers and wrists live in RE Engine games (needs REFramework): one box per finger, undo, autosave, named poses, one pose per gun. Inspired by alphaZomega's EMV Engine; in use with Visceral RE8, other RE Engine games not tried yet. [Read more](https://github.com/TefMeister/hand-poser-vr)
- **Grip Zones** (`ours_grip_zones`): a small window of sliders that moves and resizes every place the hand can grip a gun in VR (magazine, well, slide, pump or bolt, front grip), live on the gun, made to hang in the headset through Window View. Works with Visceral RE8 for now (Resident Evil Village VR); called Grab Zones until 2026-10-27. [Read more](https://github.com/TefMeister/grip-zones-vr)
- **Holster Zones** (`ours_holster_zones`): a small window of sliders that moves and resizes every holster spot on the body in VR (the quick slots, knife, medicine, ammo pouch), with a SITTING offset for playing from a chair; the sister of Grip Zones, made to hang in the headset through Window View. Works with Visceral RE8 for now. [Read more](https://github.com/TefMeister/holster-zones-vr)
- **Gun Poser** (`ours_gun_poser`): a small window of sliders that aims and moves the gun in the right hand in VR (up or down, left or right, roll, and forward, up or sideways in the hand), for one gun or all, made to hang in the headset through Window View. Works with Visceral RE8 for now. [Read more](https://github.com/TefMeister/gun-poser-vr)
- **Animation & Timing** (`ours_animation_timing`): a window plus one REFramework script that freezes, steps, slows down and nudges the player's animations in RE Engine games, with keys per frame; with Visceral RE8 it also tunes the mod's finger movements and timings live. The sister of Hand Poser; first run in a real game 2026-11-14. [Read more](https://github.com/TefMeister/animation-timing-vr)
- **CubeKit (Blender add-on)** (`ours_cubekit`): builds pixel-style models out of little cubes from a settings file: one cube size, pick any single cube, carved wear, stop-motion animation and export for GZDoom; made for the old-school shooter weapons and hands (Blender 4.2 or newer). [Read more](https://github.com/TefMeister/blender-cubekit)
- **Flat-to-VR RE toolkit** (`ours_re_toolkit`): the tested tools and the playbook for turning a flat game into VR: window capture and measuring, key, mouse and pretend-gamepad senders, shader readers that find the camera matrices, PE and export readers, and an OpenXR probe that checks the VR plumbing with no headset. [Read more](https://github.com/TefMeister/flat-to-vr-RE-toolkit)
- **Game control profiles** (`ours_control_profiles`): how to drive each game by program: recorded menu routes for Menu-o-matiC and Move-o-matiC and a KNOWN.md per game (each screen and the key past it, the controls that work, the hazards), so a session reaches gameplay without poking at keys. [Read more](https://github.com/TefMeister/ai-game-control-profiles)
- **Cross-engine VR library** (`ours_cross_engine_library`): what is publicly known about putting flat games into VR, one page per engine family (Unreal, RE Engine, id Tech, Dunia and more), with links to each project's own notes; the research lanes read it before searching the web. [Read more](https://github.com/TefMeister/flat-to-vr-cross-engine-research)
- **BeG0nE knowledge** (`ours_begone_knowledge`): the home of the BeG0nE tools: each VR fault explained (jitter, ghost hands, drifting two-handed aim, flickers), each game's fix, and what 200+ headset tests have taught so far; the recorders themselves already ship inside Lanes. [Read more](https://github.com/TefMeister/BeG0nE)
- **More terminal looks** (`ours_terminal_themes`): the other retro looks for Windows Terminal beside the green one Lanes ships with: the starburst monitor, the plain green monitor, sharp scanlines and more, each a small shader plus a colour scheme. [Read more](https://github.com/TefMeister/terminal-themes)

## Other people's tools

Downloads from other makers that help flat-to-VR work, each from its maker's GitHub. Each one is useful on its own.

- **OpenXR OBS Mirror (by elliotttate)** (`outside_obs_mirror`): lets OBS record what the headset is shown, in Direct3D 11 and 12 OpenXR games and SteamVR; the BeG0nE recording then films the headset view beside the game window (the Resident Evil games included). [Read more](https://github.com/elliotttate/OpenXR-Layer-OBSMirror)
- **xrFPS (by elliotttate)** (`outside_xrfps`): turn a controller upside down in any OpenXR game to see the frame rate and frame times as a graph, inside the headset. [Read more](https://github.com/elliotttate/xrFPS)
- **OpenXR CAS (by elliotttate)** (`outside_openxr_cas`): sharpens the headset picture (AMD's FidelityFX CAS) and adjusts colour in any OpenXR game; changes what every test sees, so it is downloaded, not switched on. [Read more](https://github.com/elliotttate/OpenXR-CAS)
- **PIX MCP (by elliotttate)** (`outside_pix_mcp`): takes apart one captured frame of a Direct3D 12 game, draw by draw, through Microsoft PIX: which pass drew what, with which textures and numbers (the RE Engine games are Direct3D 12). [Read more](https://github.com/elliotttate/pix-mcp)
- **Nsight Graphics MCP (by elliotttate)** (`outside_nsight_mcp`): the same for NVIDIA's frame tool: capture a frame of a D3D11, D3D12 or Vulkan game and read every draw, resource and timing from it. [Read more](https://github.com/elliotttate/nsight-graphics-mcp)
- **vrframework guides (by elliotttate)** (`outside_vrframework`): a 17-part guide to making a flat game VR from the outside, built on REFramework and two of mutars' ports: frame timing, one eye per frame (AFR) and its smearing, per-eye projection, HUD, input. Read, not built: its code is a scaffold. [Read more](https://github.com/elliotttate/vrframework)
- **MelonMCP (by elliotttate)** (`outside_melon_mcp`): a live connection into Unity games through MelonLoader: inspect and change the running game, the Unity cousin of the RE Engine and UEVR connectors. [Read more](https://github.com/elliotttate/MelonMCP)
- **UEVR cutscene comfort (by elliotttate)** (`outside_uevr_comfort`): a UEVR plugin that puts the camera back after a cutscene by itself, and can show cutscenes on a still screen in the room, for Unreal games such as Silent Hill 2. [Read more](https://github.com/elliotttate/uevr-cutscene-comfort)
- **UEVR RenderDoc Capture (by elliotttate)** (`outside_uevr_renderdoc`): UEVR with RenderDoc built in: grab one real Direct3D 12 frame, flat or stereo, from an Unreal game and open it in RenderDoc. [Read more](https://github.com/elliotttate/UEVR-RenderDoc-Capture)
- **UEVR 6DOF window (by elliotttate)** (`outside_uevr_6dof_window`): a UEVR fork with a comfort mode that shows the game in a stereo window you can lean around, for games that are uncomfortable in full VR. [Read more](https://github.com/elliotttate/UEVR-6DOF-Window)
